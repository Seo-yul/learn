ToolHive 학습 목차

ToolHive를 기초부터 내부 구조까지 공부하는 학습 자료이고, 마지막 편에서는 ToolHive를 우리 MCP 플랫폼과 비교한다.

기준 버전은 ToolHive v0.63.0(2026-11-06)이다. 각 편은 2026-10-14에 v0.53.0 소스와 같은 날의 공식 문서를 근거로 썼고, 2026-11-07에 v0.63.0 소스 기준으로 갱신했는데, 갱신한 내용은 각 편 머리말의 "v0.63.0 갱신 요약" 상자에 있다. 두 버전 사이의 변경은 공개 릴리스 노트(v0.54.0부터 v0.63.0까지)와 인용한 파일의 diff로 확인했다.

용어집의 뜻은 그 문서 안에서만 유효하지만, 시리즈 전체에서 뜻을 고정한 용어도 있다. "proxy"는 ToolHive가 MCP 서버 앞에 붙이는 프로세스만 뜻하고, "backend"는 vMCP가 묶는 MCP 서버만 뜻한다. "런타임"은 혼자 쓰지 않고 "컨테이너 런타임"으로만 쓴다.

proxy와 이름이 비슷한 것은 따로 부른다. 네트워크 격리에서 나가는 연결을 거르는 컨테이너는 "egress proxy"이고, thv proxy stdio 명령이 여는 연결은 "StdioBridge"다. proxy 안에서 stdio 컨테이너와 HTTP를 잇는 구현은 "stdio 변환기"라고 부른다(02편 용어집).

"registry"는 ToolHive가 읽는 목록이다. 대부분의 편은 이 목록의 MCP 서버 항목만 다루지만, 같은 목록에 skill과 plugin 항목도 들어 있다(04편 2.2절, 09편 5장). 컨테이너 이미지를 두는 곳은 registry가 아니라 "이미지 저장소"라고 부른다.

"API 서버"는 thv serve가 여는 서버다(01편, 02편). 10편에서는 우리 MCP 서버가 부르는 서버를 "REST API 서버"라고 따로 부른다.

읽는 순서

번호 순서대로 읽기를 권한다. 뒤 문서는 앞 문서의 용어와 구조를 안다고 가정하고 쓰였기 때문이다. 다만 목적에 따라 다음처럼 줄여 읽어도 된다.

  • ToolHive를 처음 본다면 01편과 02편을 먼저 읽는다.
  • operator를 만드는 사람이라면 01편, 02편, 07편, 10편을 먼저 읽는다.
  • 보안을 보는 사람이라면 03편과 05편을 먼저 읽는다.

문서와 코드가 다른 곳

이 시리즈는 문서와 코드가 다르면 코드를 따랐다. 여기서 문서는 공식 문서 사이트와 저장소 안의 설계 문서(docs/arch)를 함께 뜻한다. 아래 차이는 2026-10-14에 v0.53.0 코드로 찾았고, 2026-11-07에 v0.63.0 코드와 다시 읽은 공식 문서로 재확인했다. 재확인 결과는 모두 그대로였고, 갱신하면서 찾은 차이 두 개를 표 끝에 더했다. 근거는 각 편 본문과 참고 자료 상자에 있다.
